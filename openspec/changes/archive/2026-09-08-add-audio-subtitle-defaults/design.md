## Context

См. `proposal.md` (Why) и delta-спецификацию
`specs/playback/audio-subtitle-defaults/spec.md`. Текущее состояние:

- `resolver.resolve_video()` отдаёт HLS master-манифест (адаптив) либо прогрессивный
  muxed-файл; `default.py::play_stream` собирает ListItem и передаёт его в
  InputStream Adaptive через `setResolvedUrl`. Выбор качества уже добавлен
  (прошлый change `add-video-quality-selection`).
- Субтитры не обрабатываются вовсе: в `extract_info` yt-dlp кладёт `subtitles` и
  `automatic_captions` (с записями по языкам и форматам `vtt`/`json3`/`srv3` и
  прямыми URL), но `play_stream` ничего из этого не привязывает к ListItem —
  поэтому в плеере субтитров нет.
- Аудио: yt-dlp помечает аудио-only форматы полями `language` (например `ru`,
  `en-US`) и `format_note`, где для оригинала встречается маркер вида
  `English (US) original (default)`. На реальном Kodi для видео с русским
  оригиналом ISA/плеер выбирает по умолчанию англ. сгенерированную дорожку
  (`dubbed-auto`/`auto`), а оригинал приходится включать вручную.
- `resolver.py`/`ytlib.py` намеренно xbmc-free и покрываются desktop-тестами; UI
  и ListItem — в `default.py`. Settings.xml — legacy-формат (`<settings>` +
  `<category>` + `<setting type="select" values="...">`).

## Goals / Non-Goals

**Goals:**
- Настройка «Default audio» (Auto / Original / конкретный язык) и её применение при
  старте воспроизведения.
- Настройка «Subtitles» (Off/On) и её применение по умолчанию.
- Починить субтитры: реально доставлять субтитры из `info` в плеер Kodi.
- Сохранить xbmc-free ядро: новые helper-функции в `resolver` — чистые и
  тестируемые на desktop; ListItem/настройки — только в `default.py`.

**Non-Goals:**
- Полный per-video диалог выбора аудио/субтитров в духе NewPipe «pick before play»
  (как сделано для качества). Здесь — только default-настройки; ручной переключатель
  в плеере Kodi остаётся доступен всегда.
- Смена движка на DASH/MPD ради полной лестницы и встроенных субтитров (отдельный
  будущий change, как и качество >1080p).

## Decisions

### D1. Что понимаем под «Original» и языком — детекция из форматов yt-dlp

Аудио-дорожки берём из `info["formats"]`, где `acodec` присутствует и `vcodec`
отсутствует/`none`; язык — из поля `language`. Признак «оригинал»:
- формат, у которого `format_note` содержит маркер оригинала (ищем по
  подстрокам `"original"` / `"(default)"`, регистронезависимо) — надёжно для
  текущего вывода yt-dlp;
- если таких нет — считаем оригиналом единственную языковую дорожку, а если и её
  нет, `original` недоступен (→ Auto).

Чистые helper'ы в `resolver`:
- `audio_languages(info)` → упорядоченный список языков аудио-дорожек;
- `original_audio_language(info)` → язык оригинала либо `None`;
- `subtitle_tracks(info)` → список доступных языков субтитров (объединение
  `subtitles` и `automatic_captions`);
- `subtitle_url(info, lang)` / `subtitle_urls_for_player(info)` → URL субтитров в
  формате, который умеет плеер Kodi (предпочитаем `vtt`, затем `srv3`; `json3`
  пропускаем), см. D3.

Альтернатива (не выбрана): детект оригинала по порядку дорожек/первой с audio — 
ненадёжно при разных порядках дорожек от YouTube.

### D2. Как применяется «Default audio» на HLS

Для HLS через InputStream Adaptive аудио-дорожки находятся в самом манифесте
(EXT-X-MEDIA группы). Реализованный механизм (выбран после проверки установленной
ISA 21.5.22): ListItem-свойство `inputstream.adaptive.original_audio_language` со
значением языка (например `ru` / `en-US`). Свойство присутствует в бинарнике
установленной ISA (`strings` показал `inputstream.adaptive.original_audio_language`)
и является нативным способом ISA сообщить предпочитаемый язык аудио-группы.

- Различаем два целевых поведения:
  1. `Auto` → ничего не делаем (текущее поведение плеера).
  2. `Original`/язык → на уровне аддона определяем целевой язык `lang`:
     - `Original` → `resolver.original_audio_language(info)` (по маркерам
       `format_note`, fallback — единственная языковая дорожка);
     - конкретный тег → сам тег.
     Если `lang` определён и (для явного тега) присутствует среди языков дорожек
     (`resolver.audio_languages`), ставим свойство
     `inputstream.adaptive.original_audio_language = lang`. Если `lang` недоступен
     или не определён — не ставим ничего, оставляя выбор плееру (fallback = Auto),
     воспроизведение никогда не блокируется.

Ключевое требование к дизайну (из spec): отсутствие/недоступность запрошенной
дорожки не блокирует воспроизведение — всегда есть fallback. Настройка реализована
как аддитивное предпочтение поверх уже выбранного потока.

Альтернатива (не выбрана): пересобирать/фильтровать HLS-манифест на лету, чтобы
оставить только нужную аудио-группу, — хрупко и требует сетевой перезаписи
манифеста.

### D3. Доставка субтитров в плеер

Субтитры в HLS-манифесте YouTube обычно отсутствуют (в логах playback их нет),
поэтому их надо **прикреплять отдельно** через `ListItem.setSubtitles(urls)` —
стандартный механизм Kodi: плеер сам скачает и отобразит внешние субтитры по URL.
Настройка «Subtitles» Off/On управляет, прикрепляем ли мы их и включаем ли по
умолчанию:
- Off → не прикрепляем (или прикрепляем, но не включаем) — см. D4;
- On → прикрепляем выбранные субтитры.

Язык субтитров по умолчанию: **язык оригинала** (`resolver.original_audio_language`),
как и для звука. Это критично: если брать «первый доступный» язык из
`automatic_captions`, для не-английского ролика выбирается первый словарный
язык-перевод (например для русского ролика `ab` = `lang=ru&tlang=ab`, перевод на
абхазский), что даёт не тот трек и HTTP 429 на timedtext. Проверено на реальном
Kodi 21.3 (ролик «Что каждый разработчик должен знать про Kafka?»): при
`subtitles=On` ISA получил внешний timedtext с `lang=ru&tlang=ab` и HTTP 429 →
`Unable to create subtitle parser`. После выбора `ru` (asr, без `tlang`) timedtext
отвечает HTTP 200. Если для языка оригинала нет playable-трека — fallback на
первый доступный.

Выбор формата: Kodi из URL субтитров определяет формат по расширению/mime.
Поддерживаемые плеером удалённые форматы — `vtt` (webvtt) и `srt`. yt-dlp для
YouTube обычно отдаёт `vtt` (ручные) и `json3`/`srv3` (auto-captions). Помощник
выбирает запись с `ext == "vtt"`, затем `srv3`; `json3` пропускаем (Kodi не
парсит YouTube json3). Если vtt недоступен, а нужен перевод, доступна ручная
дорожка — берём её.

Риск: не все auto-captions отдают `vtt`. Это не блокер (spec: нет субтитров →
продолжаем без них); оставляем задачу проверки доступных форматов на реальных
видео.

### D4. Семантика «включить по умолчанию» для субтитров

Реализовано: `ListItem.setSubtitles(urls)` вызывается только при «Subtitles=On» и
наличии дорожек, причём любая ошибка привязки лишь логируется и не прерывает
воспроизведение (по spec). При «Off» или при отсутствии дорожек субтитры не
прикрепляются вовсе, поэтому по умолчанию они не показаны; пользователь при этом
не теряет возможность включить их вручную там, где дорожки прикреплены (On).
Поведение подтверждено shim-тестами: URL субтитров присутствуют в ListItem при On
и доступных дорожках и отсутствуют при Off/без дорожек. Точное поведение
отображения по умолчанию на реальном Kodi уточняется в spike 4.1 / верификации
4.3.

### D5. Настройки — legacy settings.xml

В `resources/settings.xml` добавляются:
- `default_audio` (`type="select"`): `Auto|Original|ru|en-US|uk|de|fr|es|it|pt-BR|ja|ko|zh-Hans|...` (Auto/Original обязательны; перечень языков — стартовый, значения это BCP-47-подобные теги, которые сопоставляются с `language` дорожек);
- `subtitles` (`type="select"`): `Off|On`.

Чтение в `default.py` и передача высчитанных значений в чистые helper'ы `resolver`
параметрами (никакого xbmc в `resolver`).

## Risks / Trade-offs

- [Механизм принудительного выбора аудио-дорожки в ISA/Kodi не гарантирован
  публичным API] → Проверено на реальном Kodi 21.3 (flatpak, ISA 21.5.22):
  свойство `inputstream.adaptive.original_audio_language` работает — ISA
  логирует полученное значение и стартует запрошенную дорожку (для русского
  оригинала `acont=original:lang=ru`). Подтверждено пользователем: при
  `default_audio=Original` стартует оригинальный звук; при недоступности —
  fallback на Auto, воспроизведение не ломается (согласовано со spec).
- [Auto-captions YouTube часто доступны только как `json3`/`srv3`, а не `vtt`] →
  Выбираем `vtt`/`srv3`, иначе дорожка пропускается; отсутствие субтитров не
  блокирует воспроизведение (по spec).
- [Локализованные маркеры «original»/«(default)» в `format_note` могут меняться] →
  Обработка нескольких подстрок + fallback (единственная дорожка / Auto).
- [Многоязычный список значений `default_audio` неполон] → Это стартовый набор;
  `Original` и конкретные популярные языки покрывают ключевой кейс (русский
  оригинал vs англ. auto).

## Migration Plan

- Обратная совместимость: новые настройки имеют дефолты, сохраняющие текущее
  поведение (`default_audio=Auto`, `subtitles=Off`); `play_stream` продолжает
  работать, если helper-данные отсутствуют. Старые action'ы/URL без изменений.
- Раскатка: добавить настройки + код; откат — убрать пункты настроек и привязку,
  без изменения формата хранения прошлого change.

## Open Questions

- Точный API принудительного выбора аудио-языка (настройка плеера против
  ListItem-свойства) и включения субтитров по умолчанию определяется на реальном
  Kodi в задаче верификации — это не меняет spec (в ней только наблюдаемое
  поведение с fallback'ом).
- Полный список языков в `default_audio` — можно расширять позже без изменения
  spec (это значения настройки, не требования).
