## Context

См. `proposal.md` (Why). Текущее состояние, важное для подхода:

- `resolver.resolve_video()` отдаёт HLS master-манифест (адаптив) либо прогрессивный muxed-файл,
  а `default.py::play_stream` передаёт ListItem в InputStream Adaptive (ISA).
- Аудио-настройка применяется **только** как подсказка ISA:
  `item.setProperty("inputstream.adaptive.original_audio_language", lang)`
  (`default.py:794`). Собственного выбора дорожки аддон не делает.
- Реальный лог (видео с русским оригиналом и английским авто-дубляжом): yt-dlp/ISA отдают
  **4 аудио-рендишена** — оригинал и дубляж, каждый в AAC-LC и HE-AAC. Свойство `ru` доходит до
  ISA (`kodi.log:6652`), но плеер стартует на английском дубляже (поток `1003`, `kodi.log:8137`),
  а пользователь вручную переключается (`kodi.log:8394`). Часть переключений между AAC-LC и
  HE-AAC ломает sample reader (`kodi.log:1783`, `kodi.log:1802`, `kodi.log:1810`) → тишина.
- На другом видео детекция оригинала вернула `None` (`kodi.log:1698`), после чего дорожку
  выбирал сам плеер.
- yt-dlp различает «оригинал» и «default»: `language_preference == 10` для оригинала, `== 5`
  для default (`resources/lib/yt_dlp/extractor/youtube/_video.py:3277`,
  `resources/lib/yt_dlp/extractor/youtube/_video.py:3659`). Текущий
  `resolver.original_audio_language` (`resources/lib/resolver.py:209`) смешивает их: подстрока
  `(default)` считается признаком оригинала.
- `player_monitor` уже держит процесс аддона живым после `setResolvedUrl`
  (`resources/lib/player_monitor.py:79`) — это естественный хук для выбора дорожки после старта.

## Goals / Non-Goals

**Goals:**

- Детерминированно начинать воспроизведение с оригинальной (или явно выбранной) дорожкой на HLS
  даже когда видео отдаёт несколько аудио-рендишенов, включая дубли по кодекам.
- Сохранить xbmc-free ядро: выбор дорожки описывается чистой функцией, тестируемой на desktop.
- Не блокировать воспроизведение: недоступность целевой дорожки — это fallback, а не ошибка.
- Оценить DASH/MPD как способ убрать дубли по кодекам, не реализуя его в этом change.

**Non-Goals:**

- Переход воспроизведения на DASH/MPD (только спайк) и фильтрация/переписывание HLS-манифеста.
- Дедупликация списка дорожек в меню Kodi на HLS — на HLS это свойство самого манифеста ISA.
- Per-video диалог выбора аудио (в духе выбора качества) — отдельный будущий change.
- Субтитры, качество и локальные хранилища.

## Decisions

### D1. Определение оригинала по данным yt-dlp, а не по подстрокам

Оригиналом считать дорожку, у которой `language_preference == 10` либо `format_note` содержит
маркер `(original)`. Маркер `(default)` (`language_preference == 5`) — это «дорожка по умолчанию»,
а не «оригинал»; он используется только как слабый fallback, когда явного оригинала нет. Если
маркеров нет вовсе и язык в аудио-дорожках один — fallback на этот язык; иначе оригинал неизвестен
(`None`).

Альтернатива (текущая реализация): подстроки `original`/`(default)` в `format_note` — отвергнута:
`(default)` у дубляжа даёт ложный «оригинал», а порядок форматов решает исход.

### D2. Детерминированный выбор дорожки после старта воспроизведения

После `setResolvedUrl` аддон уже наблюдает за плеером (`player_monitor`). В этом окне нужно
однократно получить список аудио-потоков плеера, выбрать по нему целевую дорожку чистой функцией
(D3) и переключиться на неё. Подсказка ISA (`original_audio_language`) сохраняется как первый
шаг, но перестаёт быть единственным механизмом.

Альтернативы: (а) полагаться только на подсказку ISA — отвергнута по логу (`ru` проигнорирован);
(б) переписывать HLS-манифест под одну аудио-группу — хрупко, требует сетевого прокси.

### D3. Чистый helper выбора дорожки

Новая xbmc-free функция принимает целевой язык/режим и список доступных дорожек (язык, имя,
кодек/индекс) и возвращает индекс выбранной дорожки или `None`. Правила сопоставления:

- нормализация языка: регистр, `_` → `-`, совпадение по базовому подтегу (`ru` ↔ `ru-RU`);
- служебные дорожки (например, descriptive/`desc`) игнорируются;
- среди дорожек одного языка предпочитается роль «оригинал», затем кодек AAC-LC перед HE-AAC;
- при отсутствии совпадения — `None` (выбор остаётся за плеером).

Альтернатива: матчинг по индексу потока — отвергнута, индексы нестабильны при смене качества.

### D4. Спайк DASH/MPD (только исследование)

Проверить на реальном Kodi, что MPD-путь даёт по одному audio `AdaptationSet` на язык (2 записи
вместо 4) и соблюдает выбор языка. Результат зафиксировать в этом файле. Реализация — отдельный
будущий change, если спайк подтвердит выигрыш.

### D5. Наблюдаемость

Логировать целевой язык, список доступных дорожек и фактически выбранную — это то, чего не хватало
при разборе `kodi.log`.

## Risks / Trade-offs

- [Плеер-API выбора аудио может отличаться в конкретной версии Kodi] → спайк на реальном Kodi 21;
  при отсутствии API поведение откатывается к подсказке ISA (не хуже текущего).
- [Короткий фрагмент неверной дорожки до переключения] → переключать сразу после готовности
  аудио-потоков, не дожидаясь конца playback-monitor цикла.
- [Индексы потоков меняются при переключении качества/рендишена] → матчинг по языку и имени,
  а не по индексу; ограниченное число повторных попыток.
- [Дубли по кодекам остаются в меню Kodi на HLS] → вне scope; адресовать в DASH-спайке.
- [yt-dlp может не отдавать audio-only форматы (например, live)] → детекция вернёт `None`,
  сработает fallback; воспроизведение не блокируется.

## Migration Plan

- Настройки и форматы хранения не меняются; при `Auto` поведение прежнее; при недоступной целевой
  дорожке — прежний fallback.
- Откат: убрать шаг переключения после старта; исправленная детекция остаётся безопасной.

## Open Questions

- Даёт ли DASH/MPD заметно более чистый список дорожек и надёжный выбор на реальном Kodi —
  отвечает спайк D4; его результат может породить отдельный change и на текущую спеку не влияет.
